### Simplified implementation (current source of truth)

Initial T06 source split policy, ports and display service into extra files. Owner
rejected that complexity. AI consolidated to three components, each with exactly
one public header, one C source and CMakeLists.txt:

- `rebuild/firmware/components/relay_driver/`: direct ESP-IDF GPIO operations;
  preload HIGH before enabling active-low output, return errors, update cached
  state only on successful writes, mark failed state unknown. Idempotent init
  preserves an already-known state. No relay contact readback is claimed.
- `rebuild/firmware/components/relay_control/`: policy helpers and the sole relay
  writer task in the same source/header. 250 ms checks, eight-entry bounded request
  queue, manual/AUTO request functions, fresh valid sensor/source/unit checks,
  recheck age immediately before output, coherent state queries. Full queue returns
  ESP_ERR_TIMEOUT; a successful enqueue is not an applied-command acknowledgement.
- `rebuild/firmware/components/lcd_display/`: actual I2C master setup and the
  prototype nibble protocol, page formatting and row cache in one source/header.
  100 kHz bus, 50 ms timeouts for every probe/transmit, first-error stop. Two 16-cell
  rows are written only when changed; cursor/row data fit one bounded transfer.
  LCD initialization failure releases device/bus resources; cleanup errors retain
  handles and are retried before new allocation. Screen clearing occurs only in
  initialization, not routine refresh. Invalid/unknown values never appear fresh.

Other integration changes:

- `rebuild/firmware/main/main.c`: sensing remains; relay control starts independently;
  LCD task now lives directly in main. LCD priority 3, sensing 5, control 6; refresh
  1 s, page rotation 3 s, failed-LCD retry 5 s. Faults pin temperature/relay status.
  Two pages show Temp/Relay and Turbidity/pH. Turbidity uses `*` for unverified
  NTU; pH retains DEFAULT. Mode and DEMO labels were removed at owner request.
  Unknown GPIO state is UNKNOWN;
  ON during a safety fault is ON UNSAFE, never falsely OFF. Ordinary OFF uses
  just OFF; unavailable turbidity uses NONE, ERROR or STALE to fit 16 columns.
- `main/CMakeLists.txt`: requires lcd_display directly, no display_service.
- `main/Kconfig.projbuild`: relay/SDA/SCL/address defaults 3/4/5/0x27. Generated
  sdkconfig and managed dependencies were not edited; owner build incorporates new
  symbols. No network, watchdog, partition or credential configuration changed.
- Existing T06 integration in sensor_service remains: bounded snapshot getter,
  hardware acquisition outside the short state/copy mutex, single sensing owner.
  The original T05 lifecycle test is retained plus a concurrent snapshot test.
- `tests/main/test_t06.c` and CMake: mock ESP-IDF GPIO/I2C APIs directly instead of
  custom port files. Verify OFF latch before output enable, mapping/error state,
  relay policy, pages, nibble encoding, timeouts, initialization cleanup and cleanup
  retry, first-error stop and row cache. Unrelated GPIO startup calls use real SDK;
  relay pin and LCD bus are simulated. Eight test cases total are registered.
- Removed obsolete `relay_port.h/.c`, `lcd_port.h/.c`, `relay_policy.h/.c` and the
