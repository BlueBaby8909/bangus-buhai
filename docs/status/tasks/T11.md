## Work completed

### Explicitly delegated AI implementation

- Added feature-organized registry router, typed HTTP schemas, transaction service,
  query repository, public-certificate/signature verification, trusted preparation
  command and [API/protocol guide](../../../rebuild/backend/features/registry/README.md).
  Reused the existing lazy pooled engine, per-operation sessions and T10 account
  checks. Main.py stayed unchanged during T11.
- Added frozen `0003_t11`; 0001/0002 remain byte-identical. Tanks/devices gain
  archival timestamps and resource versions; devices gain an optional display name.
  Five new tables bring the schema to 14 application tables plus Alembic's ledger:
  device_inventory, device_claims, device_challenges, device_configurations and
  append-only registry_audit. Existing rows are not automatically verified.
- Trusted preparation validates public certificate identity, validity/clientAuth,
  non-CA status and supported RSA key size. Unique certificate and public-key
  fingerprints prevent duplicate/shared credentials. It issues a 256-bit code
  to a new private QR-payload file outside the repository, stores only its hash
  and refuses overwrites. An explicit existing-device attachment preserves
  ownership/history and issues no claim code. No real device was prepared.
- Implemented ten-minute claim reservations and two-minute, purpose-bound,
  single-use RSA-PSS/SHA-256 device proofs. Successful proof atomically rechecks
  active user/membership/tank, establishes ownership/binding and consumes the code.
  A pending claim does not grant access; a public device ID or valid key alone
  cannot choose ownership. Concurrency, cancellation, replay and retries are explicit.
- Added desired configuration revisions/digests and separate confirmation.
  Interrupted confirmation never releases ownership. Sync after restart returns
  desired configuration; stale confirmation cannot acknowledge a new revision.
- Added create/list/detail/rename/archive/restore and retained binding history.
  Mutation versions/hatchery/device locks serialize changes; reassignment closes
  the old binding and creates a new UUID. Original event payload/provenance and
  attribution remain untouched. Archive requires unassignment; restore does not
  recreate a binding. Cross-hatchery ownership transfer is not supported.
- Reused browser sessions, CSRF/origin guards and active membership checks;
  expanded CORS to PATCH. Machine setup endpoints use proof authentication,
  separate from browser CSRF/Supabase tokens. Enforced HTTPS outside explicit
  loopback development, 16 KiB mutation bounds, safe errors and durable separate
  throttling namespaces for claiming/setup/login. Login retains its 8 KiB bound.
- Added synthetic certificate/device fixtures, two registry unit tests and 26
  registry integration tests. Extended existing discovery-based runner/CI labels;
  ordinary tests use no real Supabase/device secrets. Existing dependency pins
  were sufficient; no packages were installed or changed.
- Updated product/decision/API/setup/roadmap/status/context documents. API details,
  signing bytes and future firmware obligations are in the registry guide.
